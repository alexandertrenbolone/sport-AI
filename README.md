# Sport AI — Контент-фабрика для спортивного сайта

Тестовое задание: мини-система для генерации спортивного контента по одному матчу. Тянет реальные данные, валидирует их, генерирует четыре формата через LLM и записывает готовый файл.

## Что получается на выходе

По каждому матчу — один `.md` файл с:
- превью (~400 слов)
- прогнозом с вероятностями и ставкой
- SEO title и description
- постом для Telegram
- списком источников
- чеклистом проверки (что прошло, что вызвало сомнения)

Пример — в папке `output/`.

## Быстрый старт

```bash
git clone https://github.com/alexandertrenbolone/sport-AI.git
cd sport-AI
npm install
cp .env.example .env   # вставить GROQ_API_KEY
npm start
```

Groq — бесплатно, ключ на [console.groq.com](https://console.groq.com). TheSportsDB тоже бесплатно, без ключа.

## Как устроен пайплайн

```
TheSportsDB (бесплатный API)
         |
         v
   Fetch & Parse
   - ближайший матч АПЛ
   - форма команд (последние 5 матчей)
   - очные встречи (h2h)
         |
         v
  Validation Gate
  - дата матча не в прошлом (>3 дней)
  - данные свежие (<2 часов)
  - названия команд не пустые
         |
   FAIL -+- OK
         |         |
  стоп + |         v
  ошибка |    Parallel Generation (Groq llama-3.3-70b)
         |    +------------+-----------+------------+
         |    |  Превью    |  Прогноз  |  Telegram  |
         |    +------------+-----------+------------+
         |         |
         |         v
         |      SEO (title + description)
         |         |
         |         v
         |    Humanize Pass
         |    - второй LLM-вызов убирает AI-штампы
         |    - только для превью и прогноза
         |         |
         |         v
         |    Output Check
         |    - названия команд есть в тексте?
         |    - хэш не совпадает с недавними выводами?
         |         |
         +------>  output/YYYY-MM-DD-home-vs-away.md
```

## Как система защищается от типичных проблем

| Риск | Что делает система |
|------|-------------------|
| Модель выдумала травму или факт | В промпте явный запрет: «используй ТОЛЬКО данные ниже». Факты инжектируются напрямую из API — модель не обращается к своей базе знаний |
| Перепутала дату матча | Дата из API инжектируется в промпт как строка. После генерации валидатор проверяет, что оба названия команд присутствуют в тексте |
| Взяла старую статистику | `fetchedAt` проверяется: данные старше 2 часов — стоп и ошибка. Форма команд — только последние 5 матчей |
| Сгенерировала уверенный прогноз | Промпт запрещает: «очевидно», «явный фаворит», «гарантированно», «несомненно». Требует вероятности в % с суммой 100 |
| Заспамила ключами в SEO | Жёсткий лимит: title 50–65 символов, description 140–165. Промпт запрещает keyword stuffing |
| Выдала похожий текст, как вчера | djb2-хэш превью сравнивается с последними 10 выводами. Совпадение — предупреждение в чеклисте |
| Текст с AI-штампами | Отдельный LLM-вызов (`humanizeText`) убирает канцелярит, кальки с английского, шаблонные обороты |
| Нельзя публиковать без редактора | В выводе — `Чеклист проверки` с ошибками и предупреждениями. Ошибки блокируют генерацию, предупреждения попадают в файл — редактор видит, что именно вызывает сомнения |

## Где нужен человек

Система автоматизирует рутину, но несколько точек требуют взгляда редактора.

**Перед публикацией:**
- Превью и прогноз строятся по форме и h2h. Если у команды что-то изменилось — кадровые перестановки, скандал, смена тренера — система об этом не знает. Редактор добавляет контекст, которого нет в API.
- Прогноз всегда с оговорками о неопределённости, но ответственность за публикацию ставки — на редакторе.

**При аномалиях:**
- Файл содержит блок предупреждений. Если сработало — мало данных формы, неизвестное время матча, совпадение хэша — редактор смотрит вручную.

**Периодически:**
- Промпты устаревают. Если модель или формат API поменялся — нужен инженер.
- Качество TheSportsDB. Бесплатный API иногда не отдаёт форму команд — в таких случаях используются fallback-данные, о чём есть пометка в выводе.

## Масштаб: 300 материалов в день на 5 языков

Текущая версия — линейный скрипт, одна генерация за раз. Один матч занимает ~15–20 секунд. При переходе к производственной нагрузке меняется следующее.

**Параллелизм и очереди.** 300 материалов в день — это ~12 в час. Чтобы не накапливался долг, нужна очередь задач: BullMQ, Celery или любой message broker. Воркеры запускаются параллельно, каждый берёт матч из очереди независимо.

**Мультиязычность.** Промпты хранятся отдельно по языку (`prompts/ru/`, `prompts/en/` и т.д.). `generateContent` принимает параметр `lang`. SEO-правила по длине одинаковы для всех языков. Humanize-промпт переписывается под каждый язык — у каждого свои AI-штампы. Groq llama-3.3-70b работает на большинстве языков без смены провайдера.

**Дедупликация.** При 300 матчах в день возможны повторяющиеся пары команд. Хэш-файл переезжает в Redis или PostgreSQL. На этом масштабе дедупликация становится обязательной.

**Мониторинг.** Нужен дашборд: сколько матчей прошло валидацию, сколько упало, среднее время генерации, частота срабатывания каждого типа предупреждений. Без мониторинга проблемы обнаруживаются слишком поздно.

**Хранилище.** Сейчас вывод — локальные `.md` файлы. При 300/день это 9 000 файлов в месяц. Нужна БД или объектное хранилище (S3, Cloudflare R2) с метаданными для поиска и деплоя на сайт.

## Структура проекта

```
src/
  types.ts      - типы данных
  fetch.ts      - запросы к TheSportsDB, парсинг, fallback
  validate.ts   - проверки до генерации + форматирование факт-блока
  generate.ts   - LLM-вызовы для всех форматов
  main.ts       - оркестратор, запись файла, дедупликация
output/
  *.md          - готовый контент
```
